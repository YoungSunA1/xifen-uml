UML 2.0 十四种图

开头先放全景：结构图、行为图、交互图三组共十四种图，每种配一张示意和一句话定义；后面再拆今天那组题——三句题干分别问的是哪张图、你的答案错在哪一步，以及「活动图到底描述什么」这个争议点该怎么收口。

1 · 十四种图一览

UML 2.0 的图分三组：结构图（静态视图）7 种、行为图 3 种、交互图 4 种，合计 14 种。卡片里的示意图只画这张图最典型的画法，用来和名字对号——考选择题靠一句话定义，写论文时脑子里得有它长什么样。

没有匹配的图。

结构图 · 7 种 Structure Diagram 静态视图

类图 Class Diagram

描述类、接口、协作以及它们之间的关系，是面向对象建模中最常用的图，给出系统静态设计视图。

易错：与对象图混淆

对象图 Object Diagram

描述对象及它们之间的关系，是类图在某一时刻的实例快照。

易错：被误记成「类的结构」

包图 Package Diagram

描述模型本身分解而成的组织单元（包）以及它们之间的依赖关系。

易错：本题（2）的答案

组合结构图 Composite Structure Diagram

描述类或构件内部的结构：内部的部件、端口、连接件如何协作。

易错：与构件图混淆

构件图 Component Diagram

描述封装的类及其接口、端口，以及由构件和连接件构成的内部结构，表示系统的静态实现视图。

易错：与部署图混淆（构件图里不出现节点）

部署图（配置图） Deployment Diagram

描述运行时的处理节点以及在其内部生存的构件的配置。

易错：本题（3）的答案

制品图 Artifact Diagram

描述计算机中一个系统的物理结构：制品（文件、数据库等物理比特集合）及其关系，常与部署图配合。

易错：被用来答「节点 + 构件配置」；与构件图、部署图的辨析见第 5 节

行为图 · 3 种 Behavior Diagram 动态视图

用例图 Use Case Diagram

描述用例、参与者以及它们之间的关系，从系统外部描述功能范围。

易错：误以为它描述系统内部流程

活动图 Activity Diagram

展现一步步的控制流，以及控制流之间流动的数据（对象流），本质是流程图。

易错：本题（1）的答案；与状态机图、通信图混淆

状态机图（状态图） State Machine Diagram

描述一个特定对象的所有可能状态，以及由事件引起的状态之间的转移。

易错：与活动图混淆（一个数状态，一个数活动）

交互图 · 4 种 Interaction Diagram 动态视图

顺序图（序列图） Sequence Diagram

按时间顺序展示对象之间的消息传递，强调次序。

易错：与通信图混淆

通信图（协作图） Communication Diagram

展示对象之间的组织结构与消息传递，强调连接关系而非时间。

易错：本题（1）的坑——它是对象到对象的消息，不是计算内部一步步的流程

定时图（时序图） Timing Diagram

关注消息在时间轴上的具体执行时间与状态随时间的变化，适用于实时系统。

易错：与顺序图混淆

交互概览图 Interaction Overview Diagram

活动图与顺序图的结合：节点是交互，边是控制流，用于概览复杂的交互流程。

易错：与活动图、顺序图混淆

三组记法

  1. 结构图 7 种：类、对象、包、组合结构、构件、部署、制品——从「代码里的结构」一路排到「机房里的部署」。
  2. 行为图 3 种：用例看外部功能，活动看流程，状态机看单个对象的一生。
  3. 交互图 4 种：顺序看时间，通信看结构，定时看时刻，交互概览看全局。

2 · 题目还原

UML 2.0 所包含的图中，（1）将进程或者其他结构展示为计算内部一步步的控制流和数据流；（2）描述模型本身分解而成的组织单元以及它们之间的依赖关系；（3）描述运行时的处理节点以及在其内部生存的构件的配置。

参考答案：D、B、C ｜ 我的答案：B、A、B

空题干关键词我的答案参考答案判定依据
（1） 「计算内部一步步的控制流和数据流」 B 通信图 D 活动图 活动图的边有两类：控制流（control flow）与对象流（object flow，即数据流）。UML 2.0 里只有活动图同时讲这两条边，也只有它讲「一步步」的处理步骤。
（2） 「模型本身分解而成的组织单元以及它们的依赖关系」 A 类图 B 包图 「组织单元 + 依赖关系」是包图（package）的定义原话。类图描述的是类、接口、协作及它们之间的关系。
（3） 「运行时的处理节点以及其内部生存的构件的配置」 B 制品图 C 部署图 「运行时处理节点 + 节点内构件配置」是部署图（deployment）的定义原话。制品图讲的是软件制品（物理文件）本身。

一个旁证：（2）（3）两句几乎逐字对应包图、部署图的标准定义，说明这组题干是按教材原句出的，那么（1）那句同样是教材口径下的活动图定义。三空没有任何一空需要「理解」，都是定义题——这类题只能靠把十四种图的一句话定义背成条件反射。

3 · 「活动图描述什么」的三种说法

说法一 · 《UML 用户指南》系译本、多数中文教材与教辅的通行口径

活动图描述（系统内）从一个活动到另一个活动的控制流，本质是一种流程图；与之相对，交互图强调的是对象到对象的控制流，活动图强调的是从活动到活动。

说法二 · UML 2.0 的完整口径

活动图里的边不止一条：控制流（control flow，动作/活动的先后）与对象流（object flow，对象或数据在动作之间的流动，也就是题干说的「数据流」）；节点层面还有分叉、汇合、泳道、事件等，可表达并发与职责。用途上既能画业务流程/工作流，也能画用例实现和类操作的算法细节。

说法三 · 你手上的资料（51CTO《2026 年下半年系统分析师知识点集锦》P42）

「展现为达成某个目标而进行的一系列活动及活动之间的流转关系，可描述用例实现、类操作等的工作流程，支持并行活动建模，是系统动态视图的重要组成部分。」

怎么收口

三句说的是同一件事的三种详略程度，并不冲突。你的判断「活动图不是主要描述系统内从一个活动到另一个活动的控制流」，拆成两种读法，一真一假：

  1. 如果意思是「活动图不止于此——UML 2.0 里它还有对象流（数据流）、并发、泳道」：成立，这正是说法二。
  2. 如果意思是「活动图不描述活动之间的控制流」：不成立。「从一个活动到另一个活动的控制流」恰恰是它最经典的一句话定义，也正是 2026/9/23 这题选 D 的依据，写进论文或案例题的术语说明也不会被判错。

你要的那句定义是详略取舍的问题，不是对错的问题：教材给出一句话定义时用的是说法一，考上机/选择题时按说法一背；写论文描述「本项目用活动图做了什么」时，用说法二更完整、更好看。

4 · 这题真正的坑：把「控制流」读成了「消息流」

你选 B 通信图，说明当时脑子里「控制流」是和「消息传递」绑在一起的。在 UML 里这两种「流」分属两组图：交互图（interaction diagram，含顺序图、通信图、定时图、交互概览图）讲的是对象之间的消息，活动图讲的是处理步骤之间的控制流。题干多了「计算内部一步步」和「数据流」两个限定，就直接指向活动图。

图关注的对象一句话区分
活动图 Activity Diagram处理步骤 / 流程活动到活动的控制流，边上还可以有对象流，支持并发
状态机图 State Machine Diagram单个对象状态到状态，由事件触发转移
顺序图 Sequence Diagram对象间交互强调消息的时间次序
通信图 Communication Diagram对象间交互强调对象的组织结构（连接关系），消息带序号
用例图 Use Case Diagram系统与外部从外部看系统有哪些功能，不描述内部步骤

5 · 制品图：它是什么、算不算结构图

算，它属于结构图（静态视图）这一类。制品图（Artifact Diagram，中文也有译作「工件图」的）描述的对象不是类、不是构件，而是计算机里实实在在的「物」——制品（artifact），也就是文件、数据库、脚本这类物理比特集合。

「制品图描述计算机中一个系统的物理结构。制品包括文件、数据库和类似的物理比特集合。制品图通常与部署图一起使用。制品也给出了它们实现的类和构件。」

博客园《UML 2.0 包括 14 种图》

软考侧的说法更直白：制品图回答「系统由哪些物理文件组成，以及它们之间的关系是什么」。它的作用是把设计阶段的逻辑元素（类、构件）落成物理文件，所以通常与部署图配套使用——这也是它和构件图、部署图最容易混的地方。

图看的层面描述什么一句话记
构件图
Component Diagram		逻辑 / 设计一组可替换的软件模块（构件）及其接口、端口与依赖软件由哪些可替换的模块组成
制品图
Artifact Diagram		物理 / 文件源代码、编译产物、配置文件、脚本、数据库表等制品及其依赖；制品可标注它实现了哪些构件这些模块对应哪些物理文件
部署图
Deployment Diagram		运行时处理节点（硬件 / 运行环境）以及节点内部署的构件、制品配置这些文件跑在哪个节点上

顺带一个口径差异：十四种，还是十三种

  1. 多数教辅按 14 种算：结构图 7 种（类图、对象图、包图、组合结构图、构件图、部署图、制品图）＋行为图 3 种＋交互图 4 种。
  2. 也有资料按 13 种算，结构图只算 6 种，把制品图摘出去——知乎《UML 13 种图分类速记》的口诀就是「结构对象类和包，组件部署组合好」。
  3. 你本地那份 51CTO《知识点集锦》P41–42 只列了 12 种：制品图和交互概览图都没有出现。这份资料在制品图上是空白，遇到制品图的题别拿它对答案。
  4. UML 1.x 里还没有制品图，当时的构件图与部署图合称「实现图」，所以网上至今能看到「构件图和部署图同属于实现图」的旧说法；制品图是 UML 2.0 才新增的图。

回到今天这题：（3）问的是「运行时的处理节点以及在其内部生存的构件的配置」，落点在节点，所以是部署图。制品图只描述物理文件及其关系，图里不出现节点，答制品图就是错的。
